# Эксплуатация, обновления и расширения

[К оглавлению](README.md) · [English](../en/operations.md)

## Повседневная работа

После установки зайдите в `/login` и `/admin`. Суперадминистратор управляет настройками, пользователями, доступом, страницами, меню, темами и модулями. Доступность некоторых разделов зависит от включённых модулей. Регистрация обычных пользователей включается настройками сайта, а не автоматически при создании первого администратора.

До изменения версии CMS/модуля/темы: **сделайте ZIP-бэкап через «Администрирование → Резервные копии» и скачайте его за пределы сервера**. Убедитесь, что копия соответствует текущей версии ядра и действительно открывается. Для важных сайтов проверьте восстановление на тестовой копии.

## Обновление ядра — контейнеры

**Git Stack:** в Portainer зайдите в нужный Stack → Git / Pull and redeploy (названия кнопок зависят от версии). Обновите `main`, включите пересборку `app`, `web`, `updater`. В обычном `portainer-stack.yml` эти три образа **собираются** из репозитория, а не загружаются под именем `mcms:dev`. После деплоя проверьте `app`/MariaDB health, логи и вход в админку; при старте `app` автоматически применяются миграции.

**Compose:** `git pull --ff-only`, затем `docker compose up -d --build` в каталоге Stack. Держите копию исходных конфигураций и соответствующие старые образы/теги на случай отката.

**Подробная настройка автообновления через Portainer:** [от новой установки до получения API-ключа, ID окружения и перехода существующего Stack](portainer-auto-updates.md).

**Релизные образы GHCR:** если сознательно используете `portainer-release-stack.yml`, проверяйте существование app/web-образов выбранного тега и только после этого меняйте `MCMS_IMAGE_TAG` и redeploy. Автоматическое обновление Core с Portainer API — отдельная опция с ключом/ID Stack и закреплённым digest MariaDB; **не включайте без проверки настроек**. Встроенный Core auto-updater не гарантирует автоматический откат контейнеров/БД. Все переключатели автообновлений первоначально выключены.

## Обновление ядра — standalone

Откройте `Администрирование → Обновления`. В варианте shared hosting Portainer не используется: выберите **официальный ZIP следующего патч-релиза той же линии X.Y** (например, 0.1.8 → 0.1.9), проверьте и подтвердите обновление. Система проверяет манифест и SHA-256 файлов, делает защитный ZIP текущего сайта, подготавливает файлы и переводит сайт в обслуживание. Затем отдельный HTTP-запрос заканчивает миграции. Не закрывайте окно до завершения; если процесс оборвался, попробуйте открыть сайт ещё раз: независимый от CodeIgniter обработчик попытается вернуть старую версию.

**Ограничения:** собственные хеши внутри ZIP защищают от случайной порчи, но **не удостоверяют издателя**. Скачивайте ZIP только со страницы официального релиза; сопоставляйте его контрольную сумму с официальным источником. Обновление заменяет каталог программного кода; пользовательские файлы в `writable` сохраняются. Требуется возможность атомарного переименования каталогов на одном разделе, свободное место минимум под новую версию, старый код и бэкап. Обновление **major/minor**, несовместимое с текущими миграциями, а также обновление на хостинге с ограниченными timeouts проводите вручную с проверенной резервной копией и техническим сопровождением.

## Установка модуля

1. Откройте **Администрирование → Каталог расширений** (`/admin/extensions`) либо **Модули** (`/admin/modules`).
2. Выберите пакет из каталога или загрузите доверенный ZIP через «Установить модуль».
3. Проверьте автора, версию, совместимость с mCMS, зависимости и миграции; подтвердите установку. **Само копирование ZIP ещё не активирует модуль.**
4. Включите установленный модуль. При включении применяются его миграции и права, появляются соответствующие страницы/меню.
5. Для отключения используйте действие «Отключить»: настройки, БД и файлы сохраняются, роуты модуля перестают работать.

**Обновление модуля:** обычно требуется **сначала отключить** модуль. Перейдите в `/admin/modules/<id>/update`, загрузите новую версию, проверьте список изменений, создайте/скачайте полный бэкап, подтвердите и выполните обновление. При изменении миграций или зависимостей может потребоваться ручное восстановление БД и исходного кода. Безопасность модуля зависит от его PHP-кода — не загружайте архивы из непроверенных источников.

## Удаление модуля — два разных действия

В карточке модуля / каталоге откройте «Удалить», изучите перечень затрагиваемых ресурсов. Оба режима блокируются, если от модуля зависит **другой установленный модуль**, даже отключённый; каскадного удаления нет. Встроенные компоненты ядра не удаляются.

- **Удалить код, сохранить данные:** модуль становится отключённым, код удаляется, таблицы, настройки, медиа, миграционная история и метаданные версии сохраняются. Позже можно загрузить ZIP **точно той же версии** и включить модуль снова. Миграции должны совпадать по контрольным суммам.
- **Удалить полностью:** удаляется код и только доказанно принадлежащие модулю ресурсы. Для этого пакет должен иметь корректный `cleanup`-контракт и подтверждённую принадлежность таблиц. Если движок не может доказать безопасность удаления — **откажет**, даже администратору. Действие необратимо без бэкапа.

В обоих режимах требуется подтверждение резервного копирования. После удаления проверьте сайт; если операция прервана, используйте `/admin/extensions/recovery`.

## Темы

Через **Администрирование → Темы** загрузите доверенный ZIP, установите, настройте и активируйте. Не удаляйте активную тему: сначала переключитесь на другую. Обновление внешней темы хранит предыдущую копию кода для штатного отката. При «сохранить данные» остаются и настройки/привязки меню. Встроенные темы не удаляются. Темы, как и модули, содержат исполняемый PHP — проверяйте источник.

## Проверка обновлений

В `Администрирование → Обновления` кнопка **«Проверить»** обновляет каталог, **но сама не устанавливает пакеты**. Docker имеет отдельный контейнер `updater` (обычно проверяет каждые 6 часов), если разрешены соответствующие политики. На shared hosting без cron доступны ручные операции в админке; автоматические фоновые обновления при открытии публичных страниц не запускаются.
